Overhang + Cosine-Similarity Preprocessor — short sketch

A compact, input-agnostic preprocessor module that converts imagery and auxiliary cues into a set of mechanical stability constraints and a soft height/normal prior (cosine similarity), suitable to plug into any downstream 2D→3D optimizer (QP/SOCP/NN). Think of it as a “physics-aware front end” that hands the rest of the pipeline an interpretable constraint set and a sensible prior.

Purpose (one line)

Produce linear overhang constraints + SOC cosine priors from image-derived geometry cues so downstream solvers reconstruct physically plausible height/normal maps.

High-level structure (modules / components)

  1. IO & Preflight

    • validate inputs, choose discretization, compute pixel → world mapping (requires camera intrinsics/pose or assumed plane), estimate gravity direction.

  2. Topology & Segmentation

    • silhouette, winding-number regions, medial-axis/ridge detection, saddle detection.

    • Output: groups UkU_kUk​ (index lists), semantic masks.

  3. Support Hypothesis Builder

    • For each group: compute candidate support polygon(s) PkP_kPk​ (convex hulls, morphological supports, contact candidates).

    • Optionally produce layered supports for threshold tests.

  4. Linear Overhang Constraint Assembler

    • For each (Uk,Pk) (U_k,P_k)(Uk​,Pk​) and each polygon edge eee build linear coefficient vector a(k,e)a^{(k,e)}a(k,e) where
      ai=ne⋅(pi−qe)a_i = n_{e}\cdot(p_i - q_e)ai​=ne​⋅(pi​−qe​).

  • A: sparse matrix (m × N) for linear overhang constraints (A @ h <= b, b default 0)

  • b: RHS vector (m)

  • SOCs: list of SOC constraint descriptors (t, indices, vectors, thresholds)

  • diagnostics: maps & flags (feasibility hint, symmetry stats, constraint coverage)

  • visuals: PNG/SVG overlays for debugging

Methodology / flow (step-by-step)

  1. Preflight

    • ensure gravity_vec known (if not, estimate from horizon/IMU).

    • pick resolution NNN (pixel or patch) and compute world positions pip_ipi​.

  2. Compute topology

    • silhouette → connected components. Compute winding numbers for holes, compute medial axis and saddle points to guide grouping.

  3. Form groups UkU_kUk​

    • use connected components, ridge/saddle splits, semantic cues.

  4. Hypothesize supports

    • for each UkU_kUk​: compute candidate support set (likely contact pixels) and convex hull → polygon PkP_kPk​.

    • optionally grow support via morphological dilation to model contact uncertainty.

  5. Assemble linear COM constraints

    • for each edge eee of PkP_kPk​: compute ai(k,e)=ne⋅(pi−qe)a^{(k,e)}_i = n_e\cdot (p_i - q_e)ai(k,e)​=ne​⋅(pi​−qe​).

    • add row a(k,e)a^{(k,e)}a(k,e) to sparse matrix AAA (so constraint reads a⊤h≤0a^\top h \le 0a⊤h≤0).

  6. Build cosine priors

    • if global template vvv provided, create SOC descriptor (v, tau); if normals available, build local gradient operators GiG_iGi​ and local SOC descriptors (G_i, u_i, tau_i).

  7. Sanity & diagnostics

    • quick rank/coverage checks on AAA, visualize supports and where constraints are strongest/weakest.

  8. Export

    • produce PreprocOutput for downstream solver.

Permissible inputs (minimal → rich)

Minimal (to run basic module):

  • image I (any size), positions p_i (or camera intrinsics+pose), gravity direction.

Recommended (improves priors & supports):

  • normal map (noisy OK), bump map, albedo, silhouette/alpha, semantic/instance masks, template height v (learned or engineered).

Optional:

  • IMU/gravity, known anchor points (a pixel with fixed height), expected density map (spatially varying mass).

Possible outputs (useful to downstream)

  • Sparse A (linear COM constraints) and b (RHS).

  • SOC constraint descriptors for cosine similarity (global and/or local).

  • Initial height vector init_h (from normal integration) and optional confidence weights per pixel.

  • Support polygons and group masks.

  • Diagnostics: feasibility flag, symmetry scores, where constraints are weak/absent, visualization overlays.

Practical notes & limits (be explicit)

  • Scale ambiguity remains: constraints are homogeneous in hhh — need anchor to fix absolute scale (fix one hih_ihi​ or supply expected block height).

  • Pose / gravity required: without a notion of “down” you can’t form COM lateral tests.

  • Segmentation matters: false groupings lead to wrong supports. Start soft.

  • Computational cost: assembling AAA is cheap (sparse). Downstream solving cost depends on NNN and SOC count — multi-scale recommended.

→ feed A,b,SOCs + init_h into your QP/SOCP/ML pipeline.

Final pragmatic flourish

Treat this module as a translator: it turns topological and photometric intuition (winding numbers, saddles, normals, albedo) into algebra a solver can reason with (sparse linear inequalities, second-order cones). That algebra is interpretable: you can point to a constraint, visualize the supporting polygon, and say “this forbids that impossible cantilever.” It’s not a magic depth solver — but it makes the impossible impossible, and the plausible plausible.
